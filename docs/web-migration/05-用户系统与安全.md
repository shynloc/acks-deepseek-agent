# 05 — 用户系统与安全

> 桌面版是**单用户、无鉴权**应用：所有数据归本机，API Key 明文存 electron-store。
> 移植为多用户 SaaS 必须新建完整的用户系统、鉴权、密钥加密与数据隔离体系。本文档是新增内容（桌面版无对应代码），但所有改造都围绕"保留原功能 + 加多用户安全壳"。

---

## 1. 认证与会话

### 1.1 方案选择

| 方案 | 说明 | 推荐 |
|------|------|------|
| **JWT（短期 access + 刷新 token）** | 无状态，适合 SSE/多实例 | ✓ SSE 场景友好 |
| Session + HttpOnly Cookie | 服务端态，需共享存储（Redis） | 备选 |

> SSE 用 `EventSource` 默认不带自定义 header；若用 JWT，需把 token 放 URL query 或改用 fetch+ReadableStream 读 SSE（可带 header）。推荐 **fetch 流式读取**而非原生 EventSource，以便携带 `Authorization`。

### 1.2 密码存储
- `argon2id`（首选）或 `bcrypt(cost≥12)`。
- 绝不明文/可逆加密存密码。

### 1.3 端点（详见 02 文档第 2 节）
register / login / logout / me / refresh。

## 2. 配置与密钥迁移（electron-store → DB，核心安全改造）

### 2.1 桌面版现状（风险点）
桌面版所有配置（含 apiKey、tavilyKey、memosToken、webdav 密码、picbed 密码、embeddingApiKey）**明文存** electron-store 的 JSON 文件。单机可接受，**多用户/云端绝不可接受**。

### 2.2 迁移目标
全部迁入 `user_settings(user_id, key, value, value_enc, is_secret)` 表（见 01 文档）。

### 2.3 敏感 key 清单（必须加密 + 读取掩码）
```
apiKey, tavilyKey, embeddingApiKey, memosToken,
webdavPassword, picbedPassword
（以及插件 headers 中的密钥）
```

### 2.4 加密方案
- **信封加密**：每条密文用数据密钥 AES-256-GCM 加密；数据密钥由主密钥（KMS / 环境变量 `MASTER_KEY`）管理。
- 存储：`value_enc = base64(iv || authTag || ciphertext)`。
- **读取掩码**：API 返回敏感配置时只回 `sk-****1234`，绝不回明文；仅在后端调用上游（DeepSeek/Tavily 等）时解密使用。
- 主密钥**不入库、不入代码**，仅环境变量/KMS。

### 2.5 非敏感配置（明文 value 即可）
`baseUrl, model, maxTokens, temperature, thinkingEnabled, reasoningEffort, embeddingProvider/Model/BaseUrl, memosUrl/SyncInterval, webdavUrl/Username, picbedUrl, agentPowerMode` 等。

## 3. 数据隔离（多租户硬性要求）

### 3.1 三层隔离
1. **行级隔离**：所有业务表带 user_id，所有查询强制 `WHERE user_id = :currentUser`。
2. **会话隔离**：Agent 的 AbortController 注册表键为 `userId:conversationId`；Guardrails 每请求新建。
3. **资源隔离**：对象存储 key 前缀 `users/{userId}/`；签名 URL 限时；下载校验归属。

### 3.2 防越权（IDOR）
- 任何按 id 操作（get/update/delete note、conversation、memory、plugin、skill）都要在 SQL 同时校验 `user_id`，不可只按 id。
- 不可信任前端传来的 userId——一律从 token 解析。

### 3.3 建议：数据库层兜底
若用 Postgres，可启用 **Row Level Security (RLS)** + 每连接 `SET app.current_user`，作为应用层遗漏的兜底防线。

## 4. Agent / 工具相关安全

| 风险 | 来源 | 防护 |
|------|------|------|
| **SSRF** | 插件 endpoint_url、web_search、图床/同步 URL 用户可填 | 禁内网/保留 IP、DNS rebinding 防护、协议白名单、出口代理（详见 04 文档 4.2） |
| **服务器文件读取** | read_file/list_dir | 下线或沙箱化（04 文档 3.2） |
| **路径穿越** | write_file / 文件生成 / 用户上传 | 限定前缀、规范化路径、拒绝 `..` |
| **Prompt 注入** | 笔记内容/网页内容进入上下文 | 工具结果与系统指令隔离；防幻觉后缀已要求"基于工具实际返回" |
| **资源耗尽** | Agent 循环、大文档生成、批量 embedding | 迭代上限(已有10)、超时、并发/配额限制、生成文件大小限制 |
| **上游密钥泄露** | DeepSeek/Tavily key | 永不下发前端；后端代理；掩码返回 |

## 5. 传输与基础安全

- 全站 HTTPS；SSE 经反向代理需关 buffering（`X-Accel-Buffering: no`）。
- CORS：仅允许自有前端域。
- CSRF：JWT(Authorization header) 天然免疫；若用 Cookie 需 CSRF token。
- 速率限制：登录、AI 调用、文件生成、同步触发分别限流。
- 审计：`agent_tool_logs` 已存工具调用（加 user_id），可作安全审计基础。
- 安全响应头：CSP、X-Content-Type-Options、X-Frame-Options 等。

## 6. 合规与多用户运营（新增考量）

| 项 | 说明 |
|----|------|
| 账号删除 | 级联删除该用户全部数据（DB 行 + 对象存储前缀） + 撤销密钥 |
| 数据导出 | 复用 `export:json`（已有），满足用户数据可携带 |
| 配额/计费 | 利用 Agent usage 累计做 per-user token 配额 |
| 数据备份 | DB + 对象存储定期备份；密钥单独管理 |

## 7. 安全检查清单

- [ ] 用户系统：注册/登录/JWT/argon2id
- [ ] electron-store 全部配置迁入 user_settings，敏感值信封加密
- [ ] 敏感配置 API 返回掩码，主密钥走 KMS/env 不入库
- [ ] 所有业务 SQL 加 user_id；按 id 操作同时校验归属（防 IDOR）
- [ ] （可选）Postgres RLS 兜底
- [ ] 插件/同步/图床 URL 的 SSRF 防护
- [ ] read_file/list_dir 下线或沙箱化；write_file/生成文件防穿越
- [ ] 上游密钥永不下发前端
- [ ] HTTPS / CORS / 限流 / 安全头 / SSE 不缓冲
- [ ] 账号删除级联清理 DB + 对象存储 + 密钥
