## 2. 关键实现细节（移植必须保真）

这些是代码里的**真实行为**，文档化以防移植时丢失：

### 2.1 FTS5 全文搜索 + 高亮

- 虚表：`notes_fts USING fts5(title, content, content=notes, content_rowid=rowid)`
- 三个触发器（`notes_ai/ad/au`）在 INSERT/DELETE/UPDATE 时自动维护索引。
- 搜索查询（`db:notes:list` filter.search）：
  ```sql
  SELECT n.*, snippet(notes_fts, 1, '\x01', '\x02', '…', 20) AS search_snippet
  FROM notes n JOIN notes_fts ON n.rowid = notes_fts.rowid
  WHERE notes_fts MATCH ? ORDER BY n.updated_at DESC
  ```
  - 查询词加了 `*` 做**前缀匹配**：`filter.search + '*'`
  - 高亮用 `\x01`/`\x02` 作分隔符（前端再替换为高亮标签）
- 工具侧 `search_notes` 用 `snippet(notes_fts, 1, '【', '】', '…', 25)` + `ORDER BY rank`，并有 **FTS MATCH 语法错误的 LIKE 回退**。

### 2.2 笔记版本：自动快照 + 滚动保留 30 版

`db:notes:update` 中，当 content 或 title 变化时：
1. 先更新 notes
2. 插入一条 note_versions 快照
3. `DELETE ... WHERE id NOT IN (最近30条)` 滚动清理

### 2.3 语义搜索：embedding 文本列 + JS 余弦相似度

- embedding 以 **JSON 字符串**存在 `notes.embedding` 列。
- 检索时全表扫 `WHERE embedding IS NOT NULL`，在应用层 `JSON.parse` 后算余弦相似度（`cosineSimilarity`）。
- RAG（`buildRagContext`）阈值：`FLOOR=0.50`，`GAP_MIN=0.08`（断层检测），`MAX=3`。
- embedding provider 预设：siliconflow(bge-m3) / jina / voyage / ollama。

### 2.4 记忆系统：三层加载 + 被动遗忘曲线

`db:memories:loadContext` 的真实算法（移植必须 1:1 复刻）：
1. **被动遗忘**：`importance<4 AND recall_count<3 AND last_recalled>60天 AND created_at>60天` → 自动 `is_archived=1`
2. **Tier1 置顶**：`is_pinned=1` 最多 5 条
3. **Tier2 关键词**：对 userText 分词（中文 `[一-龥]{2,}` / 英数 `[a-z0-9]{3,}`），取前 8 词 LIKE 匹配，最多 10 条
4. **Tier3 高重要近期**：补齐至 5 条
5. 命中的记忆 `recall_count+1, last_recalled=now`

记忆 AI 整理 `db:memories:consolidate`：把全部未归档记忆喂给 DeepSeek，要求返回 `{merge,update,delete}` JSON，在事务内执行合并/更新/删除。

### 2.5 统计 Dashboard

`db:stats:get` 返回：noteCount, wordCount(SUM word_count), convCount, tokenCount(assistant 消息 tokens 和), 以及**近 7 日**每天的 notes/messages 计数（`days[]`）。

## 3. 多用户化改造（SaaS 必做）

### 3.1 核心原则

1. 新增 `users` 表。
2. **所有业务表加 `user_id`**（NOT NULL + FK + 复合索引）。
3. 所有查询强制带 `WHERE user_id = :uid`。
4. 唯一约束需**按用户隔离**：如 `tags.name UNIQUE` → `UNIQUE(user_id, name)`；`plugins.name UNIQUE` → `UNIQUE(user_id, name)`。
5. FTS/向量索引需保证按 user_id 过滤（见第 4 节）。

### 3.2 新增 users 表

```sql
CREATE TABLE users (
  id            TEXT PRIMARY KEY,           -- UUID
  email         TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,              -- argon2id / bcrypt
  display_name  TEXT,
  avatar_url    TEXT,
  status        TEXT NOT NULL DEFAULT 'active',  -- active/disabled
  created_at    BIGINT NOT NULL,
  updated_at    BIGINT NOT NULL
);
```

### 3.3 user_settings 表（替代 electron-store）

桌面版用 `new Store()` 存的所有 key（apiKey, baseUrl, model, maxTokens, temperature, thinkingEnabled, reasoningEffort, tavilyKey, embeddingProvider/Model/ApiKey/BaseUrl, embeddingPluginEnabled, memosUrl/Token/SyncInterval/PluginEnabled, webdav*, picbed*, agentPowerMode 等）统一迁入：

```sql
CREATE TABLE user_settings (
  user_id     TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  key         TEXT NOT NULL,
  value       TEXT,                 -- 普通值
  value_enc   TEXT,                 -- 敏感值密文（见 05 文档）
  is_secret   BOOLEAN NOT NULL DEFAULT FALSE,
  updated_at  BIGINT NOT NULL,
  PRIMARY KEY (user_id, key)
);
```

> 敏感 key（apiKey/tavilyKey/embeddingApiKey/memosToken/webdav 密码/picbed 密码）必须走 `value_enc` + 加密。详见 05 文档。

### 3.4 改造后业务表示例（以 notes 为例，Postgres）

```sql
CREATE TABLE notes (
  id            UUID PRIMARY KEY,
  user_id       UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title         TEXT NOT NULL,
  content       TEXT NOT NULL DEFAULT '',
  category_id   UUID REFERENCES categories(id) ON DELETE SET NULL,
  color         TEXT DEFAULT 'none',
  word_count    INTEGER DEFAULT 0,
  visibility    TEXT DEFAULT 'private',
  source_type   TEXT, source_id UUID, source_msg_id UUID,
  memos_name    TEXT, memos_synced_at BIGINT,
  embedding     VECTOR(1024),       -- pgvector，维度随 embedding 模型
  embedding_model TEXT,
  -- 全文：generated tsvector 列
  fts           TSVECTOR GENERATED ALWAYS AS (
                  setweight(to_tsvector('simple', coalesce(title,'')), 'A') ||
                  setweight(to_tsvector('simple', coalesce(content,'')), 'B')
                ) STORED,
  created_at    BIGINT NOT NULL,
  updated_at    BIGINT NOT NULL
);
CREATE INDEX idx_notes_user_updated ON notes(user_id, updated_at DESC);
CREATE INDEX idx_notes_fts ON notes USING GIN(fts);
CREATE INDEX idx_notes_embedding ON notes USING ivfflat (embedding vector_cosine_ops);
CREATE INDEX idx_notes_user_cat ON notes(user_id, category_id);
```

## 4. 三数据库方案对比与映射

### 4.1 能力映射对照

| 桌面版（SQLite） | PostgreSQL（首选） | MySQL 8（备选） |
|------------------|-------------------|----------------|
| FTS5 虚表 + `snippet()` 高亮 | `tsvector` + GIN + `ts_headline()` 高亮；或 `pg_trgm` | `FULLTEXT` + `ngram` 解析器；高亮需应用层处理 |
| FTS 前缀匹配 `query*` | `to_tsquery('词:*')` | `MATCH...AGAINST(... IN BOOLEAN MODE)` `词*` |
| embedding JSON 文本列 + JS 余弦 | `vector` 列 + `<=>` 余弦距离，DB 内排序 | 需外置向量库（Milvus/Qdrant）或存 JSON 应用层算 |
| 触发器维护 FTS | generated tsvector 列（免触发器） | generated column 或触发器 |
| 整数时间戳 BIGINT | BIGINT（保持与代码一致，避免改时间逻辑） | BIGINT |
| `crypto.randomUUID()` | UUID 类型 | CHAR(36) |

### 4.2 语义搜索的下推改造（Postgres 示例）

桌面版全表扫 + JS 算相似度，多用户下不可行。改为下推：

```sql
SELECT id, title, 1 - (embedding <=> :query_vec) AS score
FROM notes
WHERE user_id = :uid AND embedding IS NOT NULL
  AND 1 - (embedding <=> :query_vec) >= 0.50   -- 保持 FLOOR=0.50
ORDER BY embedding <=> :query_vec
LIMIT 10;
```

> 断层检测（GAP_MIN=0.08）、MAX=3 等 RAG 逻辑仍在应用层保留，与桌面版一致。

### 4.3 全文搜索 + 高亮映射（Postgres 示例）

```sql
SELECT id, title,
       ts_headline('simple', content, plainto_tsquery('simple', :q),
                   'StartSel=\x01, StopSel=\x02, MaxWords=25') AS search_snippet
FROM notes
WHERE user_id = :uid AND fts @@ plainto_tsquery('simple', :q)
ORDER BY ts_rank(fts, plainto_tsquery('simple', :q)) DESC;
```

> 保留桌面版用 `\x01/\x02` 作高亮分隔的约定，前端高亮渲染逻辑可零改动复用。

## 5. 数据迁移（存量本地数据 → 线上）

提供一次性导入工具（用户首次注册后可上传本地 `database.sqlite` 或导出的 JSON）：

1. 桌面版已有 `db:export:json`（全量导出）和 `db:import:json`（导入）。
2. 线上提供 `POST /api/import/json`：解析桌面导出格式，为当前 user_id 批量插入 notes/categories/tags/conversations/messages。
3. embedding 列：导入后触发 `POST /api/semantic/reembed-all` 重建向量（维度/模型可能不同）。
4. note_versions / memories / skills / plugins 一并迁移。
