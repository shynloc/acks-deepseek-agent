# 04 — 工具系统（19 个内置工具逐一规格 + Web 适配）

> 基于真实代码：`electron/main/tools/builtin/*`、`tools/registry.ts`、`tools/index.ts`。
> 工具通过 `toolRegistry.register()` 在 import 时**自注册**；`tools/index.ts` 统一 import 触发注册。
> 每个工具：`{ name, emoji, idempotent, maxResultChars?, schema, handler(args, ctx) }`。

---

## 1. 工具注册表机制（registry.ts，可直接平移）

- 单例 `toolRegistry`，`register/get/getAll/toApiFormat`。
- `getAll({enabledOnly})`：返回启用工具（插件可被用户禁用）。
- `toApiFormat()`：转 OpenAI function-calling 的 `tools` 格式给 DeepSeek。
- handler 签名：`(args, ctx) => Promise<string>`，ctx = `{db, store}`（**Web 加 userId**）。

**Web 改造**：注册表本身纯内存、可直接搬。唯一改动是 `getAll` 在多用户下需考虑「该用户启用了哪些插件工具」——内置工具全局共享，插件工具按用户加载（见第 4 节）。

## 3. 需重点改造的工具

### 3.1 文件生成类（generate_document / generate_docx / generate_spreadsheet / create_pptx / write_file）

**桌面版真实行为**（以 generate_document 为例）：
```ts
const dir = app.getPath('desktop')          // 存桌面
const outPath = path.join(dir, `${safeName}.html`)
fs.writeFileSync(outPath, html, 'utf8')
shell.showItemInFolder(outPath)              // 打开文件管理器
return `✅ 文档已生成并保存到桌面\n📄 文件：${basename}…`
```

**Web 适配方案**（统一改造）：
1. 生成产物在内存/临时目录得到 Buffer。
2. 上传**对象存储**（S3/R2），key 形如 `users/{userId}/generated/{uuid}.{ext}`。
3. 生成**带签名的下载/预览 URL**（限时）。
4. handler 返回文本改为：`✅ 文档已生成\n📄 文件：{name}\n🔗 下载：{signedUrl}`。
5. 前端识别返回中的下载链接，渲染为下载按钮 / 在线预览（HTML/PDF 可 iframe 预览，docx/xlsx/pptx 提供下载）。
6. 记录到 `generated_files(user_id, tool, object_key, filename, created_at)` 表，供"我的生成文件"列表与清理。

> 关键：`app.getPath('desktop')` / `shell.showItemInFolder` / `fs.writeFileSync` 全部移除，换成对象存储 SDK。生成逻辑（docx/pptxgenjs/xlsx/HTML 模板）本身**与 Electron 无关，可原样保留**。

### 3.2 文件系统读取（read_file / list_dir）—— 安全红线

**桌面版**：直接读服务器本地盘（`fs.readFileSync` / `fs.readdirSync`），单用户场景安全。

**Web 多用户**：**绝不能**读服务器本地盘（会泄露其他用户/系统文件，路径穿越风险）。三选一：

| 选项 | 说明 | 推荐场景 |
|------|------|---------|
| **A. 下线** | 移除这两个工具 | 多数 SaaS，最安全 |
| **B. 用户上传沙箱** | 改为读"用户已上传到自己空间的文件"，路径限定在 `users/{userId}/uploads/`，强校验防穿越 | 需要"让 AI 读我上传的文档"时 |
| **C. 仅 Agent 增强模式** | 桌面版有 `agentPowerMode` 配置；线上可设为高级权限用户专属，且仍走对象存储沙箱 | 进阶 |

> 推荐 **B**：保留"AI 读文件"的用户价值，但把文件来源从"服务器盘"改为"用户上传的对象存储沙箱"。read_file 的 args 从绝对路径改为 objectKey，handler 从对象存储拉取并校验归属 userId。

### 3.3 web_search（Tavily）

桌面版从 `store.get('tavilyKey')` 取 key，`net.fetch` 调 Tavily。
**Web**：key 从用户 `user_settings` 读（解密）；`net.fetch`→`fetch`；后端代理，绝不把 key 下发前端。若用户未配置 key，返回友好提示（与桌面一致）。

### 3.4 system 工具

- `get_datetime`：保留，但用**用户时区**（从 user_settings 或请求头），而非服务器时区。
- `get_system_info`：桌面版返回主机 os/cpu/mem——**多用户下泄露服务器信息**，应改为返回"服务运行环境"无敏感信息版，或直接下线。
- `get_stats`：保留，加 user_id。

## 4. 插件系统（plugins.ts）

### 4.1 真实机制
- 插件 = 一条 `plugins` 记录（endpoint_url, method, headers_json, param_schema_json）。
- `loadPluginsFromDb(ctx)`：在每次 agent run 前，从 DB 读 `enabled=1` 的插件，**动态注册**为工具（emoji 🔌）。
- handler：把模型给的 args 按 method 组装请求，`fetch(endpoint_url)`，返回响应文本。

### 4.2 Web 改造（保留 + 强制 SSRF 防护）
- `loadPluginsFromDb` 改为按 `user_id` 读该用户的插件。
- 工具注册需**按用户隔离**——不能让用户 A 的插件出现在用户 B 的工具列表。建议：Agent run 时构造**用户专属注册表视图**（内置工具共享 + 该用户插件）。
- **SSRF 防护（强制）**：用户可填任意 endpoint_url，后端 fetch 会构成 SSRF。创建/调用时必须：
  - 禁止内网/保留地址（127.0.0.0/8、10/8、172.16/12、192.168/16、169.254/16、::1、metadata 端点 169.254.169.254）。
  - 仅允许 http(s)，禁用 file://、gopher:// 等。
  - DNS 解析后再校验 IP（防 DNS rebinding），或用代理出口 + 白名单。
  - 超时 + 响应体大小限制。
- headers 中若含密钥，需加密存储（同敏感配置）。

## 5. 工具 ctx 多用户化（所有工具统一改造）

每个工具 handler 内的 SQL 都要从单库改为带 user_id：

```ts
// 桌面版
ctx.db.prepare('SELECT * FROM notes WHERE id = ?').get(id)
// Web
ctx.db.prepare('SELECT * FROM notes WHERE id = ? AND user_id = ?').get(id, ctx.userId)
```

涉及工具：search_notes / get_note / list_notes / create_note / update_note / delete_note / save_memory / recall_memories / delete_memory / get_stats。

> create 类还需写入 `user_id` 列；create_note 建议同步触发 embedding 写入（异步）。

## 6. 工具结果截断（保真）

`maxResultChars` 在 loop 中统一截断（`+ '…[结果已截断]'`）。各工具的限值见第 2 节表格，**原样保留**——这是控制 token 成本的关键。
