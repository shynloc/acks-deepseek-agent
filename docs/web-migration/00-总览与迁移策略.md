# DeepSeek Notes — Web 服务移植：总览与迁移策略

> 本文档基于**当前真实代码**（v1.0.37）整理，而非早期设计文档。
> 目标：将本地 Electron 桌面应用一比一移植为**多用户 SaaS Web 服务**，功能一个都不能少。
> 文档技术栈保持中立：给出迁移映射与多方案对比，不锁死具体框架。

## 2. 现状：真实架构（源自代码）

### 2.1 进程与职责

当前是 **Electron 单用户本地应用**，三层结构：

```
┌─────────────────────────── Electron App ───────────────────────────┐
│                                                                     │
│  Renderer (Vue 3 + Pinia)          Main Process (Node.js)           │
│  ┌────────────────────┐   IPC      ┌──────────────────────────────┐ │
│  │ views/             │◄─────────► │ agent/  Agent Loop + 流式      │ │
│  │  AIChat / Notebook │  invoke    │ tools/  18 内置工具 + 注册表   │ │
│  │  Profile / Help    │  + send    │ db/     SQLite + FTS5          │ │
│  │ stores/ 8 个 Pinia │◄──events── │ ipc/    70+ handler            │ │
│  │ services/ 渲染侧     │            │ sync/   Memos / WebDAV         │ │
│  │  deepseek/tavily 等 │            │ services/ embedding            │ │
│  └────────────────────┘            └──────────────────────────────┘ │
│            ▲   preload (contextBridge 暴露 window.api)   ▲           │
│            └───────────────────────────────────────────┘           │
│  electron-store: API Key 等配置（本地文件）                          │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 关键事实（决定移植难度）

| 事实 | 代码位置 | Web 化影响 |
|------|----------|-----------|
| Agent Loop 跑在**主进程**，直连 DeepSeek（`electron.net.fetch`） | `electron/main/agent/loop.ts` | 整体可平移到后端服务进程，无 CORS 问题 |
| 工具 handler 接收 `ctx={db, store}`，**直接读写 SQLite** | `electron/main/tools/registry.ts` | ctx 需扩展 `userId`，所有 SQL 加用户隔离 |
| 流式通过 `webContents.send('agent:delta', ...)` 推送 | `electron/main/agent/index.ts` | 改为 **SSE / WebSocket** 推送 |
| 危险操作（delete_*）走 **IPC 双向确认** | `agent/index.ts` `onConfirmNeeded` | 改为前端拦截 + 二次请求确认 |
| 配置存 **electron-store**（明文文件） | 全局 `new Store()` | 迁移到 DB `user_settings` 表 + 密钥加密 |
| 文件生成（docx/pptx/xlsx）**存桌面** | `tools/builtin/{docx,pptx,spreadsheet,files}.ts` | 改为对象存储 + 下载链接 |
| 文件系统工具（read_file/list_dir）读**服务器本地盘** | `tools/builtin/filesystem.ts` | 多用户下必须下线或改为用户上传沙箱 |
| 数据库单文件，`userData/database.sqlite` | `electron/main/db/index.ts` | 多用户需 Postgres/MySQL 或按用户分库 |
| 全文搜索用 **SQLite FTS5**（`notes_fts` 虚表 + 触发器） | `db/schema.ts` | 映射到 pgvector/tsvector 或 ES |
| 语义搜索 embedding **存 notes.embedding 文本列**，余弦相似度在 JS 算 | `services/embedding.ts` + `ipc` | 映射到 pgvector，相似度下推数据库 |

## 5. 后端技术选型矩阵（技术中立）

> 你选择了"保持技术中立"。下表给出选项与权衡，团队据此决策。

### 5.1 后端语言/框架

| 方案 | 复用现有代码 | 迁移成本 | 适用 |
|------|:-----------:|:-------:|------|
| **Node + TypeScript**（NestJS/Fastify/Express） | ⭐⭐⭐⭐⭐ Agent Loop/工具/SQL 几乎可直接搬 | 最低 | **强烈推荐** |
| Python（FastAPI） | ⭐⭐ 需重写 Agent Loop（参考 Hermes 原版反而顺手） | 中 | 团队 Python 栈 |
| Go | ⭐ 全部重写 | 高 | 高并发/已有 Go 基建 |

**移植关键洞察**：Agent Loop（`loop.ts`）、Guardrails（`guardrails.ts`）、工具注册表（`registry.ts`）、所有工具 handler 都是**纯 TS、不依赖 Electron API**（仅 `net.fetch` 可换 `fetch`，`app.getPath` 需替换）。选 Node 可将这些文件**直接复制**到后端，改动量集中在 ctx 注入与存储层。

### 5.2 数据库（详见 01 文档）

| 方案 | FTS 全文 | 向量语义 | 多用户并发 | 推荐度 |
|------|---------|---------|:---------:|:------:|
| **PostgreSQL + pgvector** | tsvector/pg_trgm | pgvector 原生 | ⭐⭐⭐⭐⭐ | **首选** |
| MySQL 8 | ngram fulltext | 需外置向量库 | ⭐⭐⭐⭐ | 备选 |
| SQLite（单文件） | FTS5（现成） | JS 余弦（现成） | ⭐ 写锁瓶颈 | 仅单租户自部署 |

### 5.3 流式传输

| 方案 | 与现有契合 | 复杂度 | 说明 |
|------|:---------:|:------:|------|
| **SSE（EventSource）** | ⭐⭐⭐⭐⭐ | 低 | 现有就是单向 token 流，SSE 最贴合；推荐 |
| WebSocket | ⭐⭐⭐ | 中 | 需双向（确认机制）时更顺，但要管连接 |

**推荐组合**：Node + TypeScript + PostgreSQL(pgvector) + SSE + 对象存储(S3/R2)。这是迁移成本最低、功能最完整的路径。

## 6. 多用户化的横切改造（贯穿所有模块）

无论选哪个栈，以下三条是多用户 SaaS 的**强制改造**，会渗透到每份文档：

1. **数据隔离**：所有业务表加 `user_id` 外键；所有查询强制 `WHERE user_id = :currentUser`；工具 ctx 注入 `userId`。
2. **配置隔离**：`electron-store` 的全局配置 → `user_settings(user_id, key, value)`，敏感值（apiKey/tavilyKey/memosToken/webdav密码）**加密存储**。
3. **会话隔离**：Agent 运行实例按 `userId + conversationId` 维度，Guardrails / AbortController 不可跨用户共享（现有按 conversationId，需升级为 `userId:conversationId`）。

## 7. 阶段路线图

| 阶段 | 目标 | 交付 |
|------|------|------|
| **P0 地基** | 用户系统 + DB 迁移 + 配置/密钥服务 | 注册登录、`user_settings`、数据隔离基线 |
| **P1 核心数据** | 笔记/分类/标签/版本/快捷方式/统计 REST 化 | 笔记本功能完整可用 |
| **P2 搜索** | FTS 全文 + pgvector 语义搜索 | 两种搜索均可用、结果高亮 |
| **P3 Agent** | Agent Loop + 18 工具 + Guardrails + SSE + RAG + 记忆 | AI 对话全功能（含工具调用） |
| **P4 文件与扩展** | 文件生成→对象存储、插件系统(含SSRF防护)、技能 | 文档生成、插件、技能可用 |
| **P5 同步与周边** | Memos/WebDAV/图床/导入导出/OCR/视觉 | 同步与全部周边功能 |
| **P6 收尾** | 桌面专属功能优雅降级、验收对照 07 清单 | 零功能缺失验收通过 |

> P0→P3 完成即可上线 MVP（对话+笔记+搜索）；P4→P6 补齐全部能力达成"一个都不能少"。

## 8. 不迁移项说明（非功能缺失）

| 项 | 原因 |
|----|------|
| 系统托盘 `Tray` | 浏览器无系统托盘概念，对应能力由浏览器标签/通知替代 |
| 自定义窗口控制 `window:minimize/maximize/close` | 浏览器原生窗口管理 |
| `read_file`/`list_dir` 读服务器盘 | 多用户安全红线；改为"用户上传文件沙箱"在 04 文档给出替代 |
| `shell.openPath`/`showItemInFolder` | 桌面文件管理器调用，Web 用下载链接替代 |

以上下线项均无对应 Web 业务语义，或已由更安全的 Web 方案替代，**不影响用户可感知功能完整性**。
