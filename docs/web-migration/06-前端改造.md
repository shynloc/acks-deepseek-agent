# 06 — 前端改造

> 基于真实代码：`electron/preload/index.ts`（window.api 结构）、`src/views/*`、`src/stores/*`、`src/services/*`、`src/data/agent-prompts/*`。
> 核心策略：**Vue 组件 / Pinia stores / 视图基本零改动**，把 `window.api`（IPC）替换为一个**同构的 HTTP 客户端适配层**，让上层代码无感知。

---

## 1. 改造总原则

桌面版前端通过 `window.api.xxx.yyy(...)` 调用（preload 用 contextBridge 暴露的嵌套对象，每个方法是 `ipcRenderer.invoke`）。

**关键洞察**：`window.api` 是一个**纯接口层**。只要在 Web 端实现一个**结构完全一致的 `window.api`**（内部改为 fetch/SSE），所有 Pinia stores 和组件**无需改动**即可复用。这是迁移成本最低的路径。

```
桌面: window.api.db.notes.list(filter) → ipcRenderer.invoke('db:notes:list', filter)
Web : window.api.db.notes.list(filter) → fetch('/api/notes?...').then(r=>r.json())
```

---

## 2. HTTP 适配层（替代 preload）

新建 `src/api/client.ts`，导出与 preload 同构的对象，挂到 `window.api` 或直接 `export const api`。

### 2.1 结构对照（保持嵌套与方法名一致）

preload 暴露的命名空间（全部需在 Web 适配层 1:1 实现）：
```

api.tavily / embedding / semantic / memos / webdav / picbed / tencentdocs / api(balance/test)
```

### 2.2 普通方法（invoke → fetch）
```ts
const http = {
  get:  (p) => fetch(`/api${p}`, { headers: authHeaders() }).then(json),
  post: (p, b) => fetch(`/api${p}`, { method:'POST', headers:{...authHeaders(),'Content-Type':'application/json'}, body:JSON.stringify(b) }).then(json),
  // patch/delete...
}
export const api = {
  db: {
    notes: {
      list:  (filter) => http.get(`/notes${qs(filter)}`),
      create:(n) => http.post('/notes', n),
      update:(id, patch) => http.patch(`/notes/${id}`, patch),
      delete:(id) => http.del(`/notes/${id}`),
      setTags:(id, tagIds) => http.put(`/notes/${id}/tags`, { tagIds }),
    },
    // ...其余按 02 文档映射
  },
}
```

> 字段命名：后端统一返回 camelCase（见 02 文档），与桌面版 `ccAll` 转换后一致，stores 无需改字段名。

## 3. Agent 流式：IPC 事件 → SSE 适配

桌面版 Agent 用**事件订阅**模式（`api.agent.onDelta(cb)` 注册回调，main 进程 `send` 推送）。Web 用 SSE 复现同一套回调接口，让 store 代码不变。

### 3.1 桌面版回调接口（需在 Web 复现）
```
api.agent.run(payload)
api.agent.abort(conversationId)
api.agent.onDelta(cb) / onToolCall / onToolResult / onDone / onError / onConfirmRequest
api.agent.confirmResponse(reqId, confirmed)
api.agent.getTools()
```

### 3.2 Web 实现（fetch 流式读取，支持携带 Authorization）
```ts
let listeners = { delta:[], toolCall:[], toolResult:[], done:[], error:[], confirm:[] }
api.agent = {
  onDelta:(cb)=>listeners.delta.push(cb),  // ...其余同理
  async run(payload) {
    const res = await fetch('/api/agent/run', {
      method:'POST', headers:{...authHeaders(),'Content-Type':'application/json',Accept:'text/event-stream'},
      body: JSON.stringify(payload), signal: currentAbort.signal
    })
    const reader = res.body.getReader(); const dec = new TextDecoder(); let buf=''
    for(;;){ const {done,value}=await reader.read(); if(done)break
      buf += dec.decode(value,{stream:true})
      // 解析 SSE: 按 \n\n 分事件，提取 event: / data:
      for (const ev of parseSSE(buf)) dispatch(ev.event, JSON.parse(ev.data))
      buf = leftover
    }
  },
  abort(cid){ currentAbort.abort(); http.post('/agent/abort',{conversationId:cid}) },
  confirmResponse(reqId, confirmed){ http.post('/agent/confirm',{reqId,confirmed}) },
  getTools(){ return http.get('/agent/tools') },
}
```

> 用 `fetch + ReadableStream` 而非原生 `EventSource`，因为 EventSource 无法带 `Authorization` header（JWT 场景）。事件分发到与桌面版同名的 listeners，**AIChat.vue / chat store 中处理 delta/tool-call/confirm 的逻辑零改动**。

### 3.3 确认弹窗
桌面版收到 `confirm-request` 弹确认框，用户操作后 `confirmResponse(reqId, ok)`。Web 同样：SSE 收到 `confirm-request` → 弹窗 → `POST /api/agent/confirm`。UI 组件不变，只是底层从 IPC 换 HTTP。

## 4. 桌面专属 UI 处理

| 桌面功能 | 代码 | Web 处理 |
|---------|------|---------|
| 系统托盘 | Tray | **移除**（无对应；可用浏览器通知 API 替代提醒） |
| 窗口控制（最小化/关闭） | `window:*` + 自定义标题栏 | **移除**自定义标题栏，用浏览器原生窗口 |
| 打开文件/文件夹 | `shell.openPath/showItemInFolder` | 改 `<a download>` / `window.open(signedUrl)` |
| 写剪贴板 HTML | `clipboard:writeHtml` | 浏览器 `navigator.clipboard.write` |
| 文件保存对话框 | `dialog.showSaveDialog` | 浏览器下载（`<a download>` 或 Blob URL） |
| 文件打开对话框 | `dialog.showOpenDialog` | `<input type=file>` multipart 上传 |
| 文档生成"已存桌面" | 工具返回桌面路径 | 工具返回签名下载链接，前端渲染下载/预览按钮 |

> 这些是少量、局部的 UI 改动，集中在标题栏组件、设置页导入导出、AIChat 工具结果渲染处。主视图（笔记本、对话、个人中心）的业务 UI 不受影响。

## 7. 构建与部署

| 项 | 桌面 | Web |
|----|------|-----|
| 构建 | electron-vite 打包 main+preload+renderer | 仅构建 renderer（Vite build）为静态 SPA |
