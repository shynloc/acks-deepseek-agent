# DeepSeek Notes 1.0.39 更新说明

补丁版本：修复三处数据写入缺陷，其中一处会导致 AI 回复丢失。**建议 1.0.37 及以上版本的用户尽快升级。**

数据格式不变，可直接覆盖安装。

**本版起提供 macOS 安装包**（Intel 与 Apple Silicon）。Windows 版随后补齐。

---

## 重要修复

### AI 回复没有存进数据库（1.0.37 起）

**这是本版最要紧的问题。** 从 1.0.37 开始，每轮对话结束时 AI 的回复都写不进数据库——回复只存在于内存里，界面上看得见，一旦切换对话或关闭应用就永久消失。同时每次都会弹出「界面错误：An object could not be cloned.」的提示。

受影响的是 1.0.37 与 1.0.38。**已经丢失的回复无法找回**——它们从未写入过磁盘。你可以打开旧对话确认：如果只剩自己发的消息、AI 的回答都不见了，就是这个问题。

同一原因还导致**对话标题不会自动生成**，侧栏里会积累一堆「新对话」。本版修复后恢复正常。

### 带标签的笔记保存失败

给笔记选中任意标签再保存时，保存会直接失败。未使用标签的笔记不受影响。

### 分类拖拽排序不生效

拖动分类调整顺序后，界面会弹回原位，顺序没有真正保存。

---

## 技术原因（同一个根因）

三处缺陷都源于同一件事：Electron 在进程间传递数据时使用结构化克隆算法，而该算法**无法序列化 Proxy 对象**。Vue 的响应式状态本身就是 Proxy，因此任何直接从界面状态里取出、未经复制就送往后台的数据，都会让整次写入调用失败。

其中 AI 回复那处是 1.0.37 的一次重构引入的：原本的写法会顺带把响应式对象转成普通对象，重构时这层转换被移除了。

本版新增了针对性的回归测试，用同样的克隆规则校验写入载荷，防止此类问题再次发生。

---

## 数据与兼容性

- 数据格式不变，无需迁移，可直接覆盖安装
- 旧版本数据库会自动平滑升级
- 笔记、对话、标签、分类、记忆等全部数据保持原样

## 安装

| 平台 | 文件 |
|---|---|
| macOS Intel | `DeepSeek Notes-1.0.39.dmg` |
| macOS Apple Silicon | `DeepSeek Notes-1.0.39-arm64.dmg` |
| Windows | 随后补齐 |

macOS 安装包未做代码签名，首次打开会被 Gatekeeper 拦下。在「应用程序」里右键点击图标并选择「打开」即可；若仍被拦，可在终端执行：

```
xattr -cr "/Applications/DeepSeek Notes.app"
```
